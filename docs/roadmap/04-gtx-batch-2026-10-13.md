# GTX 1050 Ti batch — the checks owed by P03 to P06 (2026-10-13)

P03, P04, P05 and P06 ran on the development box without stopping (the owner's request,
2026-10-13). Every check that needs the reference GPU (E-04) was queued instead of
stopping the run. This page is the one laptop session that clears the queue. Each section
cites the task's entry in `05-plan-record/`, which holds the expected numbers and the
reason. Section 10 adds the window checks that need a person but not the GTX.

Run everything at one commit, the newest on `main`, in a Release build:

```powershell

cmake --build build --config Release
```

Report as before: a zip with a README, the measure output, the raw JSON lines, and your
notes per section. Anything that is not as expected is news, not a failure of yours.

## 3. Save and load `.dcscene` (`05-plan-record/05-p03-scene-model.md` § T2)

Same two graphs open:
- Move one object (Parameters ▸ matrix), hide the other, recolour one, edit one parameter.
- `Ctrl+S`: a save dialog in the graph's folder, named `<graph>.dcscene`. Save. Status bar:
  `Saved …: 2 objects`. Check the dialog added `.dcscene` on Windows.
- Copy the `.dcscene` to the desktop, quit, `DualCEditor <desktop>\<name>.dcscene`. The
  scene shows as saved: pose, hidden object, colour, the edited parameter. **Is the image
  the same as before the save?** (NV92 cannot judge images across a relink.)
- `Ctrl+Z` does nothing after an open. Drag the `.dcscene` onto the window: it opens again.
- `Ctrl+Shift+S` asks for a name.
- Edit the original graph file in a text editor and save: opened from its own folder, the
  object reloads; opened from the desktop copy, nothing reloads.

## 4. Transform gizmo (`05-plan-record/05-p03-scene-model.md` § T3)

`DualCEditor gyroid_box.json <any second graph>`:
- Click an object: red, green, blue axes at its origin; the Transform dock shows its name
  and pose.
- `G`, move the mouse: the object follows. `X`: it slides along the red axis only, drawn
  across the view, bottom-left `Move x: … mm`. Click: one `Move <name>` step in Edit.
- `R`, `Z`, sweep around the object: it turns about z. `Esc`: back.
- `S`, move away: it grows; click.
- Type 200 in Position x, Return: the object jumps 200 mm **still whole** (no clipping at
  the old box) and **no compile line in the log**.
- `Ctrl+Z` three times: back where it was. `Ctrl+S` opens the save dialog, no scale starts.
- **Frame time while dragging** (status bar): about P07.3's numbers for this scene
  (`02-measurements.md` § GTX 1050 Ti at b163141), no new stalls during a drag. Every
  object now carries a `scale` wrapper (one divide and one multiply per evaluation) and a
  `float` uniform; this is where that cost would show.
- Scale the gyroid to 0.2 in the dock and orbit. Compare the thin walls with the same scene
  saved, closed and reopened (which recompiles). A difference means `featureScale` must
  follow the scale (the record's § T3 *Open*: the fix is to scale `featureScale` with the
  smallest object scale in `pushUniforms`).
- Save a scene with a scaled, rotated object as `.dcscene`, reopen: same pose.

## 8. Export (`05-plan-record/08-p06-export.md` § T1)

fill, `Ctrl+E`, a `.stl` name:
- Depth 8: note the dialog's estimate (triangles, RAM), export, note the log's time and
  triangle count. **Expected: the estimate within 2× of the logged count.** If not, both

  Manager is enough). **Expected: the tiled peak well under the whole one and under the
  dialog's tiled estimate.** Open both files in a slicer: watertight.
